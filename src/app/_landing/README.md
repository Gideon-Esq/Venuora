Landing page notes

The landing page shares the existing account palette: warm ivory background, off-white surfaces, indigo primary actions and ink text. Dark chapters use an indigo-tinted charcoal. The sign-in promotional shell carries the same editorial photography and display typography; authentication forms and actions are unchanged.

The homepage uses locally hosted illustrative photography and two AI-created venue images. The reception replaces an unrelated fashion portrait, and the waterfront shows a wedding venue fully prepared for guests. These images are not represented as listed venues or Venuora customer events. See image-prompts.md for prompts and asset paths.

Hero stories switch manually with an opacity crossfade. Search values persist across category changes. There is no automatic rotation or decorative continuous motion. Sections reveal once through IntersectionObserver and Web Animations, with content visible by default if animations are unavailable. Reduced motion disables entry animations, hover transitions and smooth scrolling; changing the preference cancels active reveals. Navigation highlights the section in view. Tablet and mobile galleries have previous/next buttons with disabled edge states, alongside native swipe scrolling. Search fields, cards and links provide focus and hover feedback. The footer pairs the flower icon with the title-case Venuora name in near-black on a muted warm grey (#d5d3ce) canvas. The icon is smaller than the lettering, with matching colour and balanced spacing. The back-to-top control sits with the compact footer links. Mobile venue galleries use native horizontal scrolling; the collage is simplified and the search becomes a two-column form.

Search reads only published venues with active spaces. Location matches venue name, city or region; guest count matches seated OR standing capacity. It does not verify event availability or layout suitability. The chosen date links to the relevant month on the existing venue availability page. Booking, quotes, payments and tenancy code are unchanged.

Venue-setting tiles open labelled inspiration previews because the schema does not currently expose venue-style tags. The five-step style finder provides a planning direction and can populate search fields; it explicitly does not claim matched inventory, availability, or budget filtering. Journal articles open complete original planning notes in native dialogs. Owner registration and sign-in use existing routes. Footer groups contain only supported destinations; legal, contact and social URLs must be supplied before adding those links.
